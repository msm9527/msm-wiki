# 进程管理

进程管理集中展示 MSM 托管服务的运行状态，并提供启停与重启入口。代理核心切换、更新、回家配置和网络模块也会调用同一套运行时管理能力。

![进程管理：Clash、MosDNS 与 Sing-Box 的状态和操作入口](/images/ui/process-management.png)

> 服务卡片会显示实际进程标识 `mihomo`；它对应文档中的 **Clash** 管理方案，不是另一项服务。

当前页面标题为 **托管服务**。每张服务卡片会显示运行状态和进程信息，并提供启动 / 停止、重启、服务设置和查看日志；实际按钮会随当前状态与账号权限变化。

截图中 Clash 与 MosDNS 正在运行，Sing-Box 已停止，这是“DNS + 单一活动代理核心”的正常形态。PID 和运行时长只用于判断进程是否发生过重启。

## 主要服务

| 服务 | 作用 | 注意事项 |
|------|------|----------|
| **MosDNS** | DNS 分流与缓存 | 停止后，把 DNS 指向 MSM 的客户端会解析失败 |
| **Clash** | 当前选择为 Clash Meta / Clash Smart 时的代理核心 | 与 Sing-Box 不应同时接管透明代理 |
| **Sing-Box** | 当前选择为 Sing-Box 时的代理核心 | 与 Clash 不应同时接管透明代理 |

Cloudflare 连接器、自建私网、域名反向代理和 Docker Agent 等运行时主要从各自专题页管理，是否同时出现在进程列表取决于当前版本和部署方式。

端口由当前配置和部署决定，不要只依据固定默认值。容器用户还需要区分宿主发布端口与容器目标端口。

## 服务状态

- **运行中**：进程存在；仍需检查业务就绪状态
- **启动中 / 停止中**：等待生命周期操作完成
- **已停止**：没有运行进程
- **异常**：进程退出、配置无效或就绪检查失败

“运行中”不一定代表控制器、端口或外部连接已经可用。代理核心应同时检查控制器与策略组；回家应检查监听端口；私网应检查 Peer 和路由。

## 基本操作

### 启动

1. 先校验当前服务配置
2. 确认所需端口未被占用
3. 点击启动
4. 等待状态稳定
5. 到对应服务页面执行就绪检查

### 停止

停止 MosDNS 会影响所有依赖它的客户端；停止当前代理核心会中断代理连接。执行前确认主路由和客户端有可控的恢复路径。

### 重启

常见于配置生效、临时异常恢复和组件更新。重启期间会短暂中断，完成后应查看最近日志与业务状态。

### 查看日志与服务设置

**查看日志**会带着当前服务进入统一日志页；**设置**用于该托管进程的启动参数和服务配置。修改设置前先记录旧值，保存后确认 PID、运行时长、监听端口和业务页面都恢复正常。

![统一日志页：选择服务、搜索、级别筛选、暂停与下载](/images/ui/process-logs.png)

## 代理核心切换不是普通重启

不要通过“停止 Clash，再启动 Sing-Box”手工模拟切换。应从 **代理服务 → 概览** 选择目标方案，让 MSM 完成：

- 目标核心准备
- 配置与订阅迁移
- 单一活动核心协调
- DNS 和透明代理网络规则重建
- 控制器与策略组验证

详见 [统一代理服务](/zh/guide/proxy)。

## 命令行

```bash
# 查看 MSM 状态
msm status

# 重启 MSM 主服务
msm restart

# 停止 MSM 主服务
msm stop

# 查看组件日志
msm logs mosdns
msm logs mihomo
msm logs singbox
```

CLI 命令可能控制 MSM 主服务或特定托管进程，执行前查看 `msm <command> --help`，并避免与 Web 更新、核心切换或恢复流程同时操作。

## API

服务查询与控制使用 `/api/v1/services` 路径。写操作需要相应角色和许可证能力，不能只提供一个有效登录 Token 就假设有控制权限。

```bash
# 查询服务
curl -H "Authorization: Bearer $TOKEN" \
  http://<MSM-IP>:7777/api/v1/services

# 重启 MosDNS
curl -X POST -H "Authorization: Bearer $TOKEN" \
  http://<MSM-IP>:7777/api/v1/services/mosdns/restart
```

## 故障恢复

1. 查看对应服务最近日志
2. 执行配置校验
3. 检查端口、文件权限和二进制版本
4. 运行系统诊断
5. 确认没有两个代理核心同时运行
6. 必要时从配置历史或备份恢复

同一错误连续重试不会修复无效配置。先读清第一次失败的具体阶段，再决定重启、回滚或修正配置。
