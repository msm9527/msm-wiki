# Sing-Box 核心

Sing-Box 已接入统一 **代理服务**，不再是只有配置和日志的独立实验页面。选择 Sing-Box 后，概览、节点、规则、连接、配置和远程回家入口会继续留在 `/proxy/*`，并自动切换到 Sing-Box 数据源。

MSM 当前使用 reF1nd Sing-Box 核心。日常操作先看 [统一代理服务](/zh/guide/proxy)，本页说明 Sing-Box 特有的配置方式。

## 已支持的管理能力

- 服务安装、启动、停止、重启和状态恢复
- Clash 兼容控制接口下的节点、策略组、连接和流量查看
- 订阅 Provider 管理、更新与健康检查
- 规则、规则集和策略编辑
- TUN 与通用代理参数
- 完整 `config.json` 原始编辑、校验和应用
- Shadowsocks、VLESS、Trojan、AnyTLS、Hysteria2、TUIC v5 远程回家入站
- 与 Mihomo 之间的事务化切换

不同核心的原生模型并不完全相同。界面会标记 Sing-Box 不支持的 Provider 类型、规则集格式或字段；保存时不会伪造这些能力。

## 推荐流程

1. 在 **代理服务 → 概览** 选择 **Sing-Box**
2. 等待核心准备、配置迁移、网络应用和控制器验证完成
3. 在 **代理节点** 更新订阅并执行健康检查
4. 在 **规则管理** 核对转换后的规则和出站引用
5. 在 **连接管理** 验证实际连接
6. 在 **配置编辑** 检查完整 `config.json`

## 配置编辑

Sing-Box 配置页同时提供结构化编辑和完整 JSON 编辑：

- 结构化编辑用于常见入站、出站、路由、规则集与 TUN 参数
- 原始编辑用于当前界面未覆盖的原生字段
- 结构化保存只更新对应字段，其他原生字段应继续保留
- 保存前会调用 Sing-Box 校验，运行中的核心按页面提示重启生效

如果配置含有界面无法安全投影的嵌套规则或引用，请优先使用原始 JSON，并在保存后重新查看完整文档。

## 订阅与规则转换

MSM 会把统一编辑器中的 Provider、代理和规则映射到 Sing-Box 的出站与规则集结构。跨核心迁移后建议重点检查：

- 订阅格式是否受目标核心支持
- 策略组引用的出站是否存在
- 规则集格式和下载地址是否兼容
- `route.final` 是否仍指向预期出站
- TUN、DNS 与 FakeIP 参数是否和 MosDNS、主路由一致

## 远程回家

进入 **代理服务 → 远程回家** 后，MSM 会按所选协议在当前 `config.json` 中维护 inbound，并生成 Mihomo 客户端 YAML。除 Shadowsocks 外的协议需要 TLS 证书与私钥；VLESS 和 TUIC v5 还使用 UUID。保存并应用前会验证完整 JSON；启动失败时会恢复原配置并尝试恢复旧运行状态。

详细步骤见 [远程回家](/zh/guide/home)。

## 故障排查

### 切换后订阅被跳过

目标核心不支持的 Provider 会在切换验证阶段列出。按提示更换订阅格式或在 Sing-Box 配置中使用兼容的 Provider，再重新更新。

### 页面能查看但不能编辑

查看者角色只能读取。高级配置和部分写操作还需要相应 Pro 能力；请检查用户角色、许可证和功能开关。

### 保存后服务无法就绪

1. 查看配置校验的具体字段
2. 检查出站、策略组和规则集引用
3. 查看 **代理服务 → 日志查看**
4. 使用配置历史或备份恢复上一个可用版本
