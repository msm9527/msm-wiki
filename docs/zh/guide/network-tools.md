# 网络工具

**网络工具**是 MSM 内置的诊断工作台，用于从 MSM 主机本身观察 DNS、路由、端口、证书、外网身份和局域网。结果反映的是 MSM 所在节点的网络视角，不一定等同于你的手机或电脑。

::: warning 诊断授权边界
Ping、MTR、HTTP、SSL、iPerf3 和端口扫描等工具只能用于自有或已明确授权的目标。请限定目标和端口范围，不要对随机互联网地址或超出测试委托的资产执行扫描。
:::

该模块属于 Pro 功能，并受 **系统设置 → 功能开关 → 网络工具** 控制。关闭开关后，侧边栏入口会隐藏，对应 API 也会停用。

当前界面采用“快速诊断 → 工具目录 → 单工具工作区”的运维控制台结构。顶部会持续显示 MSM 探测节点健康状态；可搜索或按分类选择工具，使用 `Ctrl+K` / `Cmd+K` 聚焦工具选择器，并把常用工具加入收藏。

## 工具目录

### 连通性

| 工具 | 用途 |
|------|------|
| **Ping** | 实时查看延迟、丢包、TTL 和 RTT 曲线 |
| **MTR** | 持续观察每一跳的延迟与丢包 |
| **Traceroute** | 查看到目标的逐跳路径 |
| **测速** | 测量下载、上传、空闲 / 负载延迟、抖动和 Bufferbloat |
| **iPerf3** | 对自建 iPerf3 服务执行上下行吞吐测试 |
| **HTTP 测试** | 自定义方法、Header、Body 和超时，检查 HTTP 响应 |

### 身份与协议

| 工具 | 用途 |
|------|------|
| **DNS 查询** | 指定记录类型、解析器和超时进行查询 |
| **IP 信息** | 查看公网 / 私网属性、地区、运营商和 ASN |
| **WHOIS / RDAP** | 查询域名或 IP 注册信息 |
| **IPv6 检查** | 检查 IPv6 地址、连通性和 NAT64 / DNS64 线索 |
| **NAT 检查** | 通过 STUN 观察 NAT 类型和端口映射特征 |
| **SSL 检查** | 查看证书主题、颁发者、SAN、链和到期时间 |

### 局域网

| 工具 | 用途 |
|------|------|
| **端口扫描** | 扫描目标端口、服务和 Banner |
| **网络接口** | 查看本机地址、收发字节、错误和丢包 |
| **ARP 扫描** | 在本地二层网络发现设备 |
| **子网计算器** | 计算网络地址、广播地址、掩码和可用范围 |
| **Wake-on-LAN** | 向目标 MAC 发送魔术包 |

部分工具需要较高系统权限；容器部署还受网络命名空间、Capabilities 和设备访问限制。页面会标记不可用或降级状态。

`iPerf3`、HTTP 测试、端口扫描和 Wake-on-LAN 只允许管理员或操作员运行。查看者仍可看到这些工具的说明，但不能启动任务；其余只读或低风险诊断可按页面权限运行。测速中的代理节点切换同样要求管理员或操作员。

## 快速诊断工作台

网络工具首页可以输入域名、IP 或 URL，并发执行基础 Ping、DNS 和 HTTP 检查。管理员和操作员会运行三项；查看者可以运行 Ping 与 DNS，但 HTTP 请求属于主动网络操作，只显示权限说明。

每个结果卡片都可以直接打开对应专业工具继续定位。快速诊断记录最多展示最近 8 次，点击旧记录可重新运行；记录与收藏保存在当前浏览器中，清除浏览器数据或换浏览器后不会自动同步。

建议先用快速诊断判断问题属于：

- 目标本身不可达
- DNS 解析异常
- HTTP / TLS 服务异常
- 主机连通、域名解析或网页响应中的哪一层

再进入下方的专业工具做深入检查，避免一开始同时运行多个扫描。

## 测速模式

测速支持两类视角：

- **互联网测试**：访问外部测速地址，观察真实上网链路
- **本机基线**：测量 MSM 内部读写和处理开销，用于判断运行环境上限

页面还会显示当前代理核心、策略组、节点和实际规则，帮助判断测速流量走直连还是代理。更换节点后先刷新路由快照，再开始新一轮测试。

外部服务可能只支持下载而不支持上传，此时结果会标记为部分测量，不应把缺失上传值当成 `0 Mbps`。

## 常用排障组合

### 域名打不开

1. **DNS 查询**：确认 A / AAAA 结果和所用解析器
2. **Ping / MTR**：检查目标地址的路径和丢包
3. **HTTP 测试**：查看状态码、Header 和响应时间
4. **SSL 检查**：核对证书域名、链和有效期

### 代理慢

1. 在 **代理服务 → 代理节点** 执行节点延迟测试
2. 在测速页确认实际规则与节点
3. 使用 Ping / MTR 比较直连与代理路径
4. 比较互联网测试和本机基线

### Docker Agent 失联

1. DNS 查询 Agent 域名
2. SSL 检查证书域名和有效期
3. 端口扫描 Agent HTTPS 端口
4. HTTP 测试健康地址
5. MTR 检查跨网路径

### 局域网设备找不到

1. 查看网络接口是否选对网卡
2. 运行 ARP 扫描
3. 对已知 IP 做 Ping 和端口扫描
4. 若在 Docker 内运行，确认容器是否能看到宿主 LAN 二层网络

## 使用边界

- 端口扫描、ARP、iPerf3、HTTP 请求和 WOL 只用于你有权测试的网络与设备
- 不要用高并发、大端口范围或长时间测速影响家庭网络
- WHOIS、IP 信息和测速依赖外部服务，失败可能来自服务商限制
- 容器中的 NAT / ARP / 接口结果描述的是容器网络，可能不是宿主机网络
- 实时任务可取消；离开页面前停止不再需要的长任务
