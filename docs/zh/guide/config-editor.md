# 配置管理

MSM 提供两种配置入口。先选对入口，再修改文件，可以避免绕过校验或让两个编辑器互相覆盖。

| 入口 | 适合内容 | 格式与生效方式 |
|------|----------|----------------|
| **服务专属编辑器** | DNS、代理策略和当前核心配置 | 了解服务结构，可校验并协调应用 / 重启 |
| **全局配置管理** | 尚未被结构化页面覆盖的 MSM 配置文件 | 文件树操作，需自行确认引用关系和生效边界 |

日常修改优先使用服务专属页面。全局配置管理适合高级维护，不应当作所有设置的快捷替代品。

![代理配置编辑入口的 Pro 能力提示](/images/ui/pro-upgrade-gate.png)

## 权限要求

- 读取完整配置树通常需要基础 Pro。
- 新建、编辑、上传、复制、重命名和删除需要配置写入能力。
- 创建历史、稳定标记、删除历史和回滚需要增强历史能力。
- 运行时应用还会检查用户角色和服务控制能力。
- 部分高风险写操作需要短期在线授权或本机授权证明。

菜单可见不表示所有按钮都可用。标准版或能力不足时会显示升级 / 锁定页，不要通过直接调用接口绕过。

## 服务专属编辑器

### MosDNS

优先在 **DNS服务 → 规则管理 / 客户端设置 / 系统功能** 修改结构化设置。只有这些页面无法表达的插件链、原始 YAML 或自定义文件，才进入 **DNS服务 → 配置管理**。

修改后至少验证：

1. MosDNS 配置校验通过。
2. 进程重启后保持运行。
3. DNS 日志能看到新查询。
4. A、AAAA、FakeIP 和分流结果符合预期。

### 代理核心

- Mihomo 使用 YAML。
- Sing-Box 使用 JSON。
- 当前活动核心从 **代理服务 → 配置编辑** 进入。
- 结构化编辑会尽量保留未修改的原生字段。
- YAML 写入会尽量保留注释和顺序，但自动迁移仍可能重排相关块。

Mihomo Smart、官方 Mihomo 和 Sing-Box 的字段并不通用。切换核心必须从 **代理服务 → 概览** 执行，不能只把当前配置文件改成另一种格式。

## 全局文件树

常见能力包括：

- 展开目录和搜索文件
- 多标签打开文本文件
- 新建文件 / 目录
- 上传、下载、复制、重命名和删除
- 按服务类型校验
- 查看历史与差异
- 标记稳定版本或回滚

二进制、数据库和未知格式文件不应当作普通文本修改。上传前确认目标目录、文件名和运行账号权限。

## 安全修改流程

1. 到 [备份恢复](/zh/guide/backup-restore) 创建备份并下载到其他设备。
2. 确认当前活动核心、服务版本和实际使用的配置路径。
3. 只在一个编辑器中打开目标文件。
4. 小范围修改，不同时重构多个无关配置块。
5. 执行格式与服务校验。
6. 查看保存差异，特别关注被自动迁移或重排的字段。
7. 保存后按页面提示应用或重启。
8. 查看进程 PID、最近日志和系统诊断。
9. 用真实 DNS / 代理请求验证业务结果。

## 配置历史与回滚

历史记录用于恢复某个配置文件或一组受支持配置，不等同于完整系统备份。回滚前先看差异：

- 目标历史是否属于当前核心和版本。
- 订阅、规则集或其他引用文件是否仍存在。
- 端口、凭据和外部路径是否适用于当前主机。
- 回滚后是否需要重启服务。

标记“稳定”只说明你确认过该版本，不会自动验证将来的组件兼容性。

## 并发修改和覆盖

不要同时在以下位置修改同一内容：

- 全局文件树与代理配置编辑器
- Web 编辑器与 SSH / 本机文本编辑器
- 自动更新迁移与手工修改
- 恢复任务与正在打开的编辑标签

保存前刷新差异；如果文件已被其他流程更新，先保留双方内容并重新合并，不要盲目覆盖。

## 校验通过但服务启动失败

格式校验通常只能证明结构有效，不能保证端口、文件、证书、上游或节点可用：

1. 查看对应服务日志的第一条错误。
2. 运行系统诊断检查端口、依赖、权限和磁盘。
3. 检查证书、规则集和 include 文件在运行环境中是否可见。
4. Docker 用户确认路径是容器内路径。
5. 必要时回滚到刚才确认的历史或备份。

## 敏感信息

配置可能包含订阅地址、代理凭据、API Token、远程回家密码、证书私钥、Cloudflare 凭据和内网拓扑。下载、截图、提交 Issue 或复制差异前必须脱敏。不要把完整配置提交到 Wiki 或公开仓库。
