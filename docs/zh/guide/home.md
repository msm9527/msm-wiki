# 远程回家

“远程回家”用于在家庭端的当前代理核心中创建公网入站，让外出设备通过公网 IP 或 DDNS 访问家庭局域网。Mihomo 与 Sing-Box 都使用同一个 **代理服务 → 远程回家** 页面。

![远程回家：准备情况、快速网络配置与配置预览](/images/ui/proxy-remote-home.jpg)

> 截图中的公网地址使用文档保留地址脱敏；请以页面对当前网络的实际检测结果为准。

::: warning 先确认适用场景
这种方式需要家庭网络具备可从公网到达的地址和端口映射。若没有公网 IP、处于 CGNAT，或不希望开放端口，请改用 [Cloudflare 云端私网](/zh/guide/cloudflare) 或 [自建私网](/zh/guide/networking)。
:::

## 工作原理

```text
外出设备
  └─ Mihomo 客户端节点（所选协议）
       └─ 公网 IP / DDNS:端口
            └─ 路由器端口转发与防火墙
                 └─ MSM 当前代理核心的入站监听器
                      └─ DIRECT 访问家庭局域网 CIDR
```

页面支持为 Mihomo 或 Sing-Box 创建以下入站协议：

| 协议 | 认证信息 | TLS | 主要传输 |
|------|----------|-----|----------|
| Shadowsocks | 密码与加密方式 | 不需要 | TCP，可同时启用 UDP |
| VLESS | UUID | 需要 | TCP |
| Trojan | 密码 | 需要 | TCP |
| AnyTLS | 密码 | 需要 | TCP |
| Hysteria2 | 密码 | 需要 | UDP / HTTP/3 |
| TUIC v5 | UUID 与密码 | 需要 | UDP / HTTP/3 |

选择协议后，表单、服务端预览、客户端 YAML 和网络转发提示都会随之变化。不要把一种协议的端口、凭据或转发方式直接套用到另一种协议。

## 准备条件

- Mihomo 或 Sing-Box 已安装并正常运行
- 家庭宽带有公网 IPv4、可入站 IPv6，或其他可到达入口
- 路由器可以配置端口转发和防火墙
- 已确认家庭 LAN 网段，例如 `192.168.1.0/24`
- 动态公网地址建议先配置 [域名服务中的 DDNS](/zh/guide/domain-services#动态域名解析)

## 配置服务端

进入 **代理服务 → 远程回家**：

1. 在 **准备情况** 中先确认监听器、公网入口、家庭网段和本机检查的状态
2. 在 **快速网络配置** 中填写公网 IP 或 DDNS；只填写域名或 IP，不要加协议、路径或端口
3. 核对家庭内网 CIDR，每行一个
4. 在监听器中选择协议、启用服务并设置端口
5. 按协议填写密码或 UUID；页面可生成强密码和 UUID
6. 使用 TLS 的协议需要填写证书、私钥和客户端使用的服务器名称（SNI）
7. 先校验配置，再保存并应用，最后执行运行检查

高级监听设置中可以修改监听器名称和监听地址；Shadowsocks 还可以选择加密方式和是否启用 UDP。`::` 会监听 IPv6，并在系统支持时接受 IPv4。

::: warning TLS 文件必须能被代理核心读取
VLESS、Trojan、AnyTLS、Hysteria2 和 TUIC v5 的证书与私钥字段是服务端文件路径，不是把 PEM 正文粘贴到表单。容器安装时，这些路径必须位于代理核心容器实际可见的位置。客户端的 SNI 应与证书域名匹配；只有明确理解风险时才启用“跳过证书验证”。
:::

## 配置端口转发

### 二进制或宿主机安装

在家庭主路由上，将公网侧所选端口转发到 MSM 主机相同的监听端口，并在路由器和主机防火墙中放行。Shadowsocks 按页面设置转发 TCP 或 TCP + UDP；VLESS、Trojan、AnyTLS 使用 TCP；Hysteria2、TUIC v5 使用 UDP。

### Docker 安装

链路多一层端口映射：

```text
公网端口 → MSM 宿主机发布端口 → 容器目标端口 → 代理核心监听器
```

页面会显示已检测到的 Docker 映射。代理核心监听端口必须与容器的 **目标端口** 一致；外出客户端和路由器端口转发使用宿主机的 **发布端口**。

如果映射只绑定到 `127.0.0.1`，局域网和公网设备无法连接。修改 Compose 端口后需要重建容器，再回到页面重新检测。

## 导入客户端配置

配置完整后，页面会生成：

- 当前 Mihomo 或 Sing-Box 核心的服务端配置预览
- 可复制到外出设备 Mihomo 配置中的客户端 YAML

客户端规则应让家庭 LAN CIDR 命中生成的回家节点，并放在 `MATCH` 等兜底规则之前。家庭端的监听器会使用 `DIRECT` 访问这些 LAN 网段。

预览包含密码、UUID、公网入口和证书验证设置，只能复制到可信设备。草稿尚未保存并应用时，不要先把预览分发给客户端。

## 运行检查

保存并应用后点击 **运行检查**。MSM 会检查：

1. 当前核心的完整配置是否有效
2. 当前核心服务是否运行
3. 当前协议要求的 TCP、UDP 或 TCP + UDP 监听端口是否由代理核心持有
4. 是否已经填写公网入口信息

::: danger 本机检查不等于公网可达
MSM 无法从家庭网络外部证明端口转发、防火墙、运营商 CGNAT 或公网路由已经正确。最终必须关闭手机 Wi-Fi，或使用真正位于外网的设备访问家庭 LAN 地址。
:::

## 配置安全与回滚

- 保存前使用当前活动核心校验完整配置
- 核心正在运行时，“保存并应用”会重启当前核心并等待监听器就绪
- 应用失败会恢复原配置，再尝试恢复旧核心运行状态
- 密码和 UUID 会写入当前核心配置，请不要粘贴到日志、工单或公开聊天
- 重新生成密码或 UUID 后，所有已导入旧凭据的设备都必须同步更新

## 常见问题

### 本机检查通过，但外网无法连接

- 检查是否真的拥有公网地址，出口 IP 不代表可入站
- 按协议确认转发类型：TCP、UDP 或两者
- 检查宿主机防火墙、云安全组和上级光猫
- Docker 用户确认发布端口、目标端口和监听端口的对应关系
- 用家庭网络之外的连接测试

### 可以连接，但访问不到家中设备

- 核对客户端规则中的家庭 LAN CIDR
- 确认规则位于兜底规则之前
- 检查家庭设备自身防火墙和回程路由
- 多个 LAN 网段需要逐行加入配置

### 保存时提示 Docker 端口不一致

把监听端口改成页面显示的容器目标端口，或者修改 Compose 映射并重建容器。不要只修改公网发布端口而忽略容器目标端口。

### 切换代理核心后怎么办？

切换到另一个核心后，重新进入 **代理服务 → 远程回家** 检查配置，执行校验和运行检查，再确认客户端参数没有变化。
